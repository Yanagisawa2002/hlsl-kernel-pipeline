# Frozen external comparison protocol

`unified-declaration.json` fixes the 8 Scan and 16 Radix cells, five independent
processes per cell, all input seeds and complete execution orders before formal
sampling. The declaration is generated by `tools/unified_protocol.py` and committed.
The final source commit, fresh Release output and its binary lock are recorded by
every process receipt. Development probes and pilots are not formal evidence.

Each process prepares separate resident resources for every arm and slot, uploads
identical logical input to each implementation, and checks complete output hashes
against a CPU oracle twice with different poisoned scratch/output bytes. An
incorrect implementation remains in the planned schedule as an explicit missing
timing; other implementations continue independently. Correct arms repeat the
same complete checks after sampling. A post-check failure invalidates their times.

Warmup is exactly eight batches of six operations per valid arm. Twelve measured
blocks follow. Each block uses a preregistered permutation and its reverse; each
arm observation contains exactly 18 complete operations. One/three resident slots
execute 18/6 times respectively in each batch. Scan covers all 24 four-arm
permutations; Radix covers its six permutations four times. Removing a failed arm
retains balanced permutations of the remaining arms, verified by synthetic tests.
No workload, parameter, warmup length, sample count or seed is chosen from times.

GPU total includes required input restoration, scratch initialization, every
dispatch and barrier, final consumer conversion and timestamp overhead. The same
five markers per operation and two outer markers apply to all arms. No marker
cost is subtracted. Stage times and individual operation timestamps are retained;
individual times exclude the gap between consecutive operations' boundary markers,
while the primary outer batch total includes that gap. Upload and verification
readback, CPU fixture/oracle and plan construction, preparation, recording, close,
submission, fence waiting and reset are separately named. Readback is outside
measurement, and CPU waiting is never substituted for GPU duration.

The primary ratio is numerator total GPU time divided by denominator total GPU
time. Each half-block time is divided by 18; the two observations form a block
mean. Log ratios are averaged over 12 paired blocks, then summarized across five
independent processes with a two-sided Student t 95% interval (df=4). Repeated
operations do not increase the independent sample count. Per-process CV uses
24 batch means; drift compares the final three versus first three block means.
p95/p99 use linear interpolation of 432 correlated operation timestamps per arm
and process and are descriptive tails, not independent statistical replicates.

Acceptance requires both arms to pass all checks in all five processes; each
arm/process CV <= 5% and drift <= 15%; all five p95 ratios >= 1.01; and the paired
lower confidence bound >= 1.01. Otherwise the comparison is inconclusive or
not comparable due to correctness. All unordered pairs are reported in declared
arm order, without familywise adjustment or a universal-winner claim. There is
no automatic default promotion. Native exceptions stop the entire experiment
epoch; statistical failure causes no retries or additional sampling.

Run the source-lock verifier, Release build, Core tests and Python protocol tests
under the shared validation wrapper for a reproduced validation session. Create a
fresh binary lock listing source SHA and every file under the executable directory
as `{path, sha256}`; relative paths are used in this lock. Then execute:

For a fresh reproduction from the delivery revision, PowerShell 7, Python and
the .NET 10 SDK are required. The checked-in build helper performs these steps
under the same public mutex wrapper and writes the binary lock automatically:

```powershell
tools/Build-UnifiedBenchmark.ps1 -OutputDirectory .hlslperf/reproduction-build
$build = Get-Content -Raw .hlslperf/reproduction-build/build.json | ConvertFrom-Json
tools/Invoke-UnifiedMatrix.ps1 -Runtime $build.runtime `
  -OutputRoot .hlslperf/reproduction-raw -Declaration $build.declaration `
  -BinaryLock $build.binaryLock -ExpectedSourceSha $build.sourceSha `
  -SerializedValidationRunner $build.serializedValidationRunner
python tools/unified_protocol.py analyze docs/integration/unified-declaration.json .hlslperf/reproduction-raw .hlslperf/reproduction-audit
```

The delivery adds documentation, audit and reproduction helpers after the
measurement commit; the frozen runtime source and statistical rules are unchanged.
For an existing independently recorded build, the explicit runner arguments are:

```powershell
tools/Invoke-UnifiedMatrix.ps1 -Runtime <release/hlslperf-unified.dll> `
  -OutputRoot <new-evidence-root> `
  -Declaration docs/integration/unified-declaration.json `
  -BinaryLock <binary-lock.json> -ExpectedSourceSha <built-commit> `
  -SerializedValidationRunner <Invoke-SerializedValidation.ps1>
python tools/unified_protocol.py analyze docs/integration/unified-declaration.json <evidence-root> <new-audit-directory>
```

The matrix acquires the shared R9700 lock separately for each native process and
holds it until exit. Restarting its wrapper skips only complete matching evidence;
it never overwrites or retries a failed process. A new reproduction necessarily
has new process identities and records its own device/compiler/binary metadata.
GPU clocks, global cache state, residency and unrelated user workloads are not
controlled. Resident slots mean actual distinct allocations, not a claim of a
measured cache-hit rate. Published conclusions apply only to the recorded R9700,
driver, inputs and cost boundaries.
