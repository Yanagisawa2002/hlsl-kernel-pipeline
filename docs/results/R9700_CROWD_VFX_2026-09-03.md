# R9700 GPU-driven Crowd/VFX evidence — 2026-09-03

## Outcome

The application proof passed two independent, complete D3D12 matrix runs from
source commit `c32b85a404059be72e6dcc2a6732d664032f3051`. The first run is the
predeclared primary result; the second is reported as replication rather than
being substituted wherever it happened to be faster.

- 1,224 candidate executions: 2 runs × 4 pressure levels × 153 candidates;
- 13,464 recorded complete-plan GPU timestamp samples;
- 1,224/1,224 compiled and 1,224/1,224 matched the independent CPU oracle;
- 1,087 candidates met the 5% CV budget; all 137 noisy candidates remain in the
  raw evidence and were excluded from selection;
- every declared baseline and selected result was correct and stable;
- all eight candidate checkpoints completed with all 153 entries;
- the second run reproduced every 24,883,200-byte four-level GPU atlas exactly.

The strongest whole-plan interval is the 8,388,608-agent extreme level. The
primary run measured 5.09944 ms versus 2.74194 ms, or **1.8598×**. The
replication measured 5.10692 ms versus 2.73256 ms, or **1.8689×**.

![Actual GPU Crowd/VFX deadline comparison](r9700-crowd-vfx-budget-crossing.gif)

## Device and measurement contract

- GPU: AMD Radeon AI PRO R9700, adapter LUID `77354`
- Driver: `32.0.31041.1004`
- Backend / shader model: D3D12 / SM 6.6
- Compiler integration: Vortice.Dxc 3.8.3.0
- OS: Microsoft Windows 10.0.26200
- Protocol: `gpu-timestamps-poison-reexecute-v1`
- Candidate order: sequential and exhaustive within each level
- Samples: 11 calibrated timestamp batches per candidate
- Stability: CV ≤ 5%; noisy candidates are recorded but cannot win
- Correctness: poison the complete atlas with `0xA5`, rerun the already-timed
  plan, read it back, and require its SHA-256 to equal the CPU oracle

GPU timestamps include all application passes and barriers: visibility,
compaction, tile histogram/offsets, tile scatter, and tiled compute raster for
twelve frames. Upload, readback, hashing, command-fence waits, CPU composition,
and GIF/MP4 encoding are excluded.

finished below it. The compositor therefore followed its declared fallback and
chose 3.940305 ms, strictly between optimized p95 and baseline median. The media

backlog, missed deadlines, and remaining work replay the recorded sample arrays

## Reproduce

From commit `c32b85a404059be72e6dcc2a6732d664032f3051` on Windows with a D3D12
device and .NET 10:

    dotnet build HlslKernelPipeline.slnx -c Release
    dotnet test HlslKernelPipeline.slnx -c Release --no-build
    dotnet run --project src/HlslPerf.GpuDrivenDemo -c Release --no-build -- validate
    dotnet run --project src/HlslPerf.GpuDrivenDemo -c Release --no-build -- run --level all --budget-ms 8.333333 --output .hlslperf/gpu-driven-demo/<new-run-name>

Never reuse an existing output name for an independent replication. Check the
new `gpu-driven-summary.json`, four `run.json` files, content-addressed atlas
hashes, pressure grid, and media timestamps.

## Limits

- These are single-GPU, single-driver, single-compiler D3D12 results.
- Candidate blocks are sequential, not randomized or interleaved; confidence
  intervals and paired randomized measurement remain v0.7 work.
- The result is a complete synthetic application pipeline, not a whole Unity
  frame and not an `ExecuteIndirect` graphics backend.
- No RGA/RGP/PIX/runtime-counter result was captured here, so register pressure,
  runtime occupancy, cache misses, bandwidth, power, and cross-vendor behavior
  are not claimed.
